# Enterprise Linux 9 RPM preview

Nebula's RPM is an alpha preview, `0.1.0~alpha`, for Enterprise Linux 9
x86_64. It is built from source in an AlmaLinux 9 container using the EL9 ABI;
it does not repackage the Debian-built executable. Final release acceptance is
tracked in [ROADMAP](../ROADMAP.md).

## Build and verify

From the checkout, with the existing Docker daemon:

```sh
./scripts/dev.sh build-rpm-image
./scripts/package-check.sh rpm
```

Qt and development tools remain inside the Docker image. The source is mounted
read-only; build output uses the ignored `build-container-rpm/` directory. Build,
CTest and installed-application checks run without networking. Image preparation
downloads dependencies from signed AlmaLinux and EPEL repositories with CRB enabled.
No host packages, repositories or global library paths are modified.

Output is `build-container-rpm/packages/nebula-0.1.0~alpha-x86_64.rpm`. The checker
reads the filename generated by CMake and prints its SHA-256 checksum after
successful verification. The installed version is `0.1.0~alpha` with RPM release
`1.el9`. The RPM is unsigned. The builder's exact installed package versions are
recorded in `build-container-rpm/package-environment.txt`.

The AlmaLinux base is pinned by digest in `Dockerfile.dev` and the runtime
verification recipe. Dependency repositories are live, not frozen to a package
snapshot. Retain the image IDs and package inventory with build results; bit-for-bit
reproducibility is not established. This does not change the Debian recipe.

## Runtime and installation

The RPM dynamically links the system Qt and SQLite libraries and bundles no
third-party libraries. The desktop needs compatible Qt 6 packages from EL9/EPEL,
certificate trust and fonts. RPM automatically records ELF library requirements;
the current artifact requires Qt 6.10 runtime symbols from EL9/EPEL.
Qt's GUI plugin package, certificates and DejaVu Sans are explicit dependencies.
EPEL/CRB access must be configured for the target distribution to resolve those
dependencies. RHEL uses CodeReady Linux Builder rather than AlmaLinux's CRB name.
Dependency licensing remains separate from Nebula's MIT license.

Download the `.rpm` and `SHA256SUMS` from the
[0.1-alpha release](https://github.com/oppenheimmer/nebula/releases/tag/0.1-alpha).
On a suitably configured EL9 desktop, run from the download directory:

```sh
sha256sum --check --ignore-missing SHA256SUMS
sudo dnf install ./nebula-0.1.0~alpha-x86_64.rpm
nebula --version
nebula
```

For a locally built package, use its path under `build-container-rpm/packages/`.
Those are desktop installation instructions, not commands the build/check scripts
run on the host. The application menu entry also launches Nebula. The workspace
chooser suggests `~/Document/nebula/`; workspaces remain outside package-owned
directories. See [USER_GUIDE](USER_GUIDE.md) and the
[backup/recovery instructions](INSTALL.md) before replacing an installation.

## Verification and limits

The RPM checker builds with GCC and warnings as errors, runs the full CTest suite,
then installs the package offline in a clean EL9 runtime without a compiler or
CMake. It checks package payload integrity, version metadata, installed docs,
fresh/opened workspaces, window editing/search, TLS previews, retained attachments,
JSON/Markdown export, lossless import, and backup/restore into fresh folders.
An unprivileged fixture also verifies that reinstall, removal and reinstall
preserve its workspace. There is no earlier public RPM upgrade baseline.

Actual results and image/compiler/library versions belong in the roadmap work
log. These container checks use offscreen Qt, without a native desktop, OS IME or
screen reader. They do not establish native RHEL desktop acceptance or support
for every RPM distribution. The existing [release checklist](RELEASE_CHECKLIST.md)
and data-handling limits still apply. AppImage packaging is not implemented.
